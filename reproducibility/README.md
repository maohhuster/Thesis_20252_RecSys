# Reproducibility — LLM-MovieLens

This directory is the one-command reproduction surface for every paper-canonical numerical claim. **No GPU required.** Runs in ~60 seconds on any laptop.

## What is verified

`verify_headline_numbers.py` checks **53 paper-canonical cells** across 5 sections:

| Section | Coverage | Source files |
|---|---|---|
| 1. Table 4 (main results, ML-20M) | 12 configs (M0, M1, M1c, M2, M2b, M3, M4, M7, R1, R1-plus, R2, R3) × 2 metrics (NDCG@10, MRR), minus R3's unreported MRR = 23 aggregate cells | hard-coded per-seed values for M-configs (paper-canonical spreadsheet snapshot) + `code/benchmark/results/r{1,1plus,2,3}_metrics.json` for Tier-3 |
| 2. Table 11 (paired *t*-tests, ML-20M) | 10 comparisons: M4 vs. each baseline (M1, M1c, M2, M2b, M3), M7 vs. M4, and M4/M7 vs. Tier-3 R1, R2 (R1-plus & R3 ML-20M appear in rows 3-4) | computed inline from the same per-seed arrays via `scipy.stats.ttest_rel` |
| 3. Density chain (R1-gene + R1-plus vs M7) | 8 cells = 2 methods × 4 datapoints (ML-20M / sub-ML-20M / ML-1M / Amazon) | `code/benchmark/results*/r{1,1plus}_*_metrics.json` |
| 4. Replacer cross-density (R2 + R3 vs M7) | 8 cells = 2 methods × 4 datapoints (ML-20M / sub-ML-20M / ML-1M / Amazon) | `code/benchmark/results*/r{2,3}_*_metrics.json` |
| 5. SASRec cross-density (vs M1) | 3 cells = ML-20M / ML-1M / Amazon | `code/benchmark/results*/sasrec_pmixer/...` per-seed dirs |

A passing run prints `ALL CHECKS PASSED. Released artifact reproduces every headline number in the paper.`

## How to run

```bash
# from the repository root
python3 reproducibility/verify_headline_numbers.py
```

Requirements: Python 3.10+, `numpy`, `scipy`. No PyTorch, no embeddings, no training. The script consumes the released per-seed JSON files and computes mean ± std + paired-*t* inline; it then compares against paper-cited values with a tolerance of `±0.0005` on aggregates and `±1.0 pp` on chain deltas. The significance-band check accepts at-or-stricter than the paper's claim.

## What the script does NOT do

It does not retrain models. Full retraining is ~10 GPU-hours; the training pipeline lives in `code/benchmark/` (entry point `code/benchmark/run_experiment.py`, per-config runners in `scripts/`).

## Files in this directory

| File | Purpose |
|---|---|
| `verify_headline_numbers.py` | The 53-cell one-command verifier |
| `artifact_index.json` | Machine-readable manifest of all 18 (method × datapoint) cells — paths, SHA-256 hashes, NDCG values, evaluation commands. Auto-generated by `scripts/build_artifact_index.py`; powers the human-readable `REPRODUCTION_INDEX.md` table at the repo root. |
| `artifacts/<method>/<datapoint>/` | Unified symlink view per cell: `checkpoints/seed-{42,123,456,789,2026}.pt` + `result.json` (or `result-seed-42.json` for SASRec). 108 symlinks total; real files stay in their tool-native locations (`code/benchmark/checkpoints*/`, `code/benchmark/results*/`). |
| `expected_output.txt` | Reference verifier output (for offline diff or sanity-check without running Python) |
| `README.md` | This file |

## Reproducing a single (method, datapoint) cell

Each cell in `artifacts/` carries the runnable eval command in `artifact_index.json`:

```bash
# Example: R1-plus ML-20M
python3 -c "import json; e=json.load(open('reproducibility/artifact_index.json'))['entries']; print(next(x['eval_cmd'] for x in e if x['method']=='R1-plus' and x['datapoint']=='ML-20M'))"
# → "python3 scripts/eval_ml20m_r1plus.py --device mps"
```
